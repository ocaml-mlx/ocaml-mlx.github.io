Ecosystem

mlx adds a syntax dialect to your existing OCaml project. Keep your compiler, language server, build system, and libraries.

Your existing OCaml workflow

Install mlx, add its editor and formatter tools, and tell Dune how to handle .mlx files. After syntax preprocessing, the compiler and downstream tools work with ordinary OCaml expressions and artifacts. You do not need a separate compiler, build system, or language server.

OCaml LSP already works with mlx

Use the standard ocaml-lsp-server. OCaml LSP added mlx support in version 1.25.0; there is no mlx-specific LSP fork to install. With a compatible language-server version, ocamlmerlin-mlx installed, and (merlin_reader mlx) in the Dune dialect, Merlin can read the syntax on behalf of the language server. Your editor can use its usual OCaml language-server integration for diagnostics, completion, and navigation.

Editor syntax highlighting still needs support for the .mlx extension. The Editor support guide lists the available integrations.

Two editor and formatter adaptations

Beyond the mlx syntax package itself, two tools adapt the parts of the workflow that must read or write JSX source:

  • ocamlmerlin-mlx. The mlx-specific Merlin parser and reader extension. It teaches Merlin to read .mlx source and supplies an OCaml syntax tree to the existing editor tooling.
  • ocamlformat-mlx. The OCamlFormat fork that understands JSX syntax and preserves it when formatting .mlx files.

These are the two mlx-specific editor/formatter tools. Keep the standard ocaml-lsp-server, Dune, and OCaml compiler. A compile-only setup can use mlx-pp without either companion tool.

Tell Dune about the dialect

The dialect maps .mlx to an implementation source, runs mlx-pp to produce an OCaml syntax tree, and selects the reader and formatter. Your library and executable stanzas continue to declare their dependencies and PPX processors in the normal way.

Copy the dialect from Installation, or read How it works for each field and the compilation steps.

The rest of the ecosystem

  • ppxlib and PPX processors. They receive an OCaml syntax tree. A JSX-aware PPX can use the [@JSX] marker to implement a library's component conventions. Other PPX processors keep their usual roles in the project's preprocessing chain.
  • js_of_ocaml. It compiles the OCaml bytecode produced after syntax preprocessing and compilation. It does not need its own mlx parser.
  • Melange. It compiles the resulting OCaml code to JavaScript through its existing Dune integration. Choose the runtime libraries and PPX your browser application needs.
  • odoc. It works from the compiler's documentation artifacts. The JSX syntax is handled earlier in the build, rather than by a separate documentation compiler.
  • opam and Dune. Install dependencies, build libraries and executables, and run tests with the same package manager and build commands you already use.

mlx changes how you write expressions, not which runtime renders them. See Libraries for React, HTML, terminal, and desktop integrations.

Try mlx in a browser

The Melange Playground has an OCaml (MLX) mode. Use it to try the syntax without installing the toolchain.
