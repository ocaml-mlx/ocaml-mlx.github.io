JSX syntax

Write JSX expressions inside OCaml. This guide covers tags, attributes, children, fragments, and the syntax limits that matter when you write .mlx files.

Start with an OCaml expression

A .mlx file is OCaml with JSX expressions. You can bind an element with let, return one from a function, or put one inside another OCaml value. mlx does not supply HTML elements or a renderer: the functions and modules in your project decide what each tag means.

This small component needs no UI library. Its createElement function accepts a unit argument, a labeled title, and labeled children. Real libraries define their own element types and component signatures.

A component in a .mlx file
module Card = struct
  let createElement () ~title ~children =
    (title, children)
end

let example = <Card title="News">"Hello"</Card>

The examples below use placeholder modules such as Ui. Use the names and types from your chosen library. For compiler and PPX details, see How it works.

Name a tag

A lowercase tag, such as <div />, calls a function named div. An uppercase tag, such as <Card />, calls the module’s createElement function. For a qualified name, the last segment decides: <Ui.button /> names the function Ui.button; <Ui.Icon /> names the module Ui.Icon and its createElement function. A runtime PPX can interpret these calls differently.

Names and module paths
let page =
  <Ui.Layout>
    <Ui.button disabled=false>"Save"</Ui.button>
    <Ui.Icon />
  </Ui.Layout>

Use OCaml identifiers and module paths for tag names, not arbitrary HTML names such as <my-widget />. Match the whole opening and closing name: <Ui.Layout>...</Ui.Layout>. A self-closing tag has an empty body; <Card></Card> has one too.

Pass attributes

Attributes are labeled OCaml arguments. required=true passes a Boolean value; a bare readonly passes the variable readonly, not true. Write label instead of label=label when a variable has the same name. The called function sets the accepted labels and their types.

Attributes and optional arguments
let field ~label ?placeholder ~readonly () =
  <Ui.input
    label
    ?placeholder
    readonly
    required=true
    width=(max 1 (String.length label))
  />

Use ?placeholder to pass an existing optional argument. Use ?placeholder=(Some hint) to pass a chosen optional value. These forms use OCaml optional arguments; they do not make an HTML attribute optional by themselves.

Optional value and a parenthesized expression
let search ~hint ~count () =
  <Ui.search
    ?placeholder=(Some hint)
    count=(count + 1)
    onChange=(fun value -> print_endline value)
  />

Use OCaml names for attributes

Attribute names must be lowercase OCaml identifiers. OCaml keywords such as class, type, method, and open cannot be attribute names. Use the actual label defined by your library, often class_ or type_. mlx does not remove the underscore or rename the label. A hyphenated HTML name such as aria-label is not an OCaml attribute name; follow your library’s convention instead.

Use expressions as attribute values

You can use OCaml literals, identifiers, constructors, variants, field access, lists, arrays, records, and even another JSX element as values. Dereferences such as !value and object method calls such as object_#method_ are also expressions. Parenthesize a compound expression: a function call, negative number, operator expression, if, match, fun, let, or type annotation. The compiler checks each value against the receiving function's type.

OCaml expressions as attribute values
let view ~count ~items () =
  <Ui.panel
    state=`Ready
    fallback=(<Ui.empty />)
    options=[1; 2; 3]
    positions=[|0; count|]
    config={ width = count; items }
    value=(if count > 0 then count else 1)
  />

For example, write size=(to_size count). Without parentheses, size=to_size count is a size attribute plus a separate punned count attribute. For a JSX-valued attribute, parentheses also keep = separate from the tag's <: write fallback=(<Ui.empty />). A braced value such as config={ width = count } is an OCaml record, not JSX interpolation. There is no props spread such as <Ui.panel ...props />.

Write children as OCaml values

Put expressions between an opening and closing tag. Separate children with whitespace or newlines. Quote literal text: "hello world" is a string, while hello world is two variables. Whitespace between children does not produce a text node. mlx does not convert other values to strings; your runtime decides what children it accepts.

Quoted text, variables, and expressions
let greeting ~name ~count () =
  <div>
    ("Hello, " ^ name)
    <span>(string_of_int count)</span>
    (if count = 1 then "item" else "items")
  </div>

Use parentheses for one compound child. <div>string_of_int count</div> has two children, the function and its argument. Write <div>(string_of_int count)</div> instead. You can write (match x with ...), (let x = ... in ...), or (value : type_name) the same way. Combine text and a variable into one child with ("Hello, " ^ name).

Place elements inside other OCaml code

An element is an expression, not a separate template file. It can be a list or array item, a record field, or a function argument without parentheses. Ordinary OCaml syntax around the element remains available.

Elements in ordinary OCaml values
let entries = [<Ui.row>"First"</Ui.row>; <Ui.row>"Second"</Ui.row>]
let columns = [|<Ui.column />; <Ui.column />|]
let page = { view = <Ui.row>"Ready"</Ui.row>; count = 1 }
let result = render <Ui.row>"Done"</Ui.row>

Use OCaml comments

Write (* ... *) between attributes or children. Comments do not create attributes or children. They follow the usual OCaml comment rules.

OCaml comments between attributes and children
let note =
  <Ui.note
    title="Notice"
    (* This comment is not an attribute. *)
    level=2
  >
    "Read this"
    (* This comment is not a child. *)
    <Ui.link>"More"</Ui.link>
  </Ui.note>

Pass children in one place

An element always passes a children argument, even when its body is empty. You can supply an existing value with a punned children attribute or with children=value. An optional ?children follows the same rule. Pass children either as an attribute or between tags, not both. The latest upstream parser rejects an explicit children or ?children combined with nested content; an empty body is allowed.

Forward children as an attribute
let forward children =
  <Card children />

let empty_body children =
  <Card children></Card>

Group with fragments (mlx 0.12+)

A fragment uses <> and </> without a named tag. It can be empty, contain multiple children, or nest inside an element or another fragment. A nested fragment stays one child in its parent; mlx does not flatten it automatically. The chosen runtime decides how fragments render.

Empty, nested, and parenthesized fragments
let empty = <></>
let pair = <><Header /><Footer /></>
let inside = <Ui.panel><>"Left" "Right"</></Ui.panel>
let nested = <><> "one" </><> "two" </></>
let argument = consume (<> "before" "after" </>)

Unlike an element, a fragment passed directly as a function argument needs parentheses: consume (<>"one"</>). Fragments arrived in mlx 0.12; do not use them with an older version.

Spread one children value (mlx 0.12+)

When you already have a children value, prefix it with ... inside an element or fragment. The spread must be its only child. It passes the existing value directly rather than adding it as one item of a new children list. Parenthesize a function call after the dots. Spaces around the dots are optional.

Forward an existing children value
let forward children = <Card>...children</Card>
let mapped items = <Card>...(List.map render_item items)</Card>
let grouped children = <>...children</>

<Card>"first" ...rest</Card>, <Card>...rest "last"</Card>, and the equivalent mixed fragments are syntax errors. <>...children</> marks the existing value as a fragment. The dots do not spread attributes.

Keep delimiters and operators distinct

Closing names must match: <Ui.Card>...</Ui.Card> cannot close as </Card> or </>. A fragment must close with </>. OCaml’s <> inequality operator and the </> operator remain available. Inside a fragment, parenthesize an operator expression so it cannot be mistaken for the fragment delimiter.

Operators and parentheses near JSX
let less_than = a < b
let unequal = a <> b
let child = <Ui.row>(a < b)</Ui.row>
let fragment = <>(a <> b)</>
let custom_operator = <>(a </> b)</>

Put spaces around a less-than comparison, a < b: without a space, a<b can be read as the start of a JSX tag. Parenthesize comparisons inside children and attribute values. The sequence >... is reserved for children spread, so an operator beginning with it is unavailable in mlx 0.12. Some operator prefixes adjacent to fragment delimiters also changed in 0.12; check the 0.12 release notes if you use custom symbolic operators.
