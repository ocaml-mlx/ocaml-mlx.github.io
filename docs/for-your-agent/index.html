For your agent

Give your coding agent the mlx setup and syntax guides, then review its OCaml with your project's tools.

Why JSX still matters

JSX keeps the tree of elements and components visible in the source. Nested tags show which children belong to which parent, and labeled attributes sit beside their values. This makes an agent's output easier for you to read and review than a long chain of construction calls. It does not guarantee that the output matches your intent.

In mlx, JSX-shaped expressions become OCaml calls. You can use ordinary OCaml expressions inside them, and the compiler checks the resulting calls and labels against the functions in your project. The selected library supplies the behavior; mlx does not choose a runtime. Read the JSX syntax guide and how mlx works for the source forms and their translation.

Skills for your agent

Use the setup skill to configure a project and the syntax skill when writing or reviewing .mlx files. The skill files are hosted on GitHub; access to the repository is required.

Setup mlx

Install the toolchain, register the Dune dialect, check editor and formatter support, and verify the build.

JSX syntax

Check element calls, props, children, component signatures, and expressions that need parentheses.

Working in an existing project

Tell your agent which runtime and UI library the project uses. Ask it to follow the project's component signatures and attribute names instead of assuming that JSX has the same meaning in every stack. Use the setup skill if the toolchain is missing, then the syntax skill for .mlx edits. Run the project's build, type checks, and formatter, and review the resulting view. Compiler feedback can catch invalid calls and labels, but it cannot confirm that the interface meets your requirements.
