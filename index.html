What is JSX?

A way to write nested elements and components in OCaml source, without adopting a new UI runtime.

Read the syntax guide →

mlx translates JSX-shaped expressions into OCaml calls marked with [@JSX]. A downstream PPX or library defines what those calls produce.

Tags, attributes, and children stay close to the code around them. Your build, types, and choice of rendering stack remain part of the OCaml project.

Installation

Install mlx, then tell Dune how to read and format .mlx files.

Complete setup →
$opam install mlx ocamlformat-mlx ocamlmerlin-mlx
dune-project
(dialect
 (name mlx)
 (implementation
  (extension mlx)
  (merlin_reader mlx)
  (format
   (run ocamlformat-mlx %{input-file}))
  (preprocess
   (run mlx-pp %{input-file}))))

Editor and formatting support through ocamlmerlin-mlx and ocamlformat-mlx.

Born on the web, designed for everything

Build for the browser, server, terminal, or desktop. Choose the application runtime first; use mlx where the stack supports its syntax.

In the browser

Melange compiles OCaml to JavaScript. reason-react supplies the component model and interprets JSX calls for a browser interface. Try mlx in the Melange Playground → without installing anything.

On the server

Dream can serve HTML produced with html_of_jsx. The JSX-shaped source is rendered by that stack, not by mlx itself.

Terminal interfaces

Mosaic provides terminal widgets and layout with mlx-ready helpers. See a view excerpt →

Desktop applications

mlui provides OCaml views for desktop windows, with flexbox layout and animations. Read desktop notes →

Typed markup

TyXML-oriented integrations can keep typed HTML construction. Check the PPX and attribute conventions used by your project.
