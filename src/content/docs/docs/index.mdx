mlx adds JSX syntax to OCaml while keeping the parser and tooling story deliberately small. The docs are organized around three needs: getting the syntax wired in, understanding how it lowers, and choosing the runtime path that matches your stack.

## What belongs where

- Reach for **Installation** when you need the dialect block, formatter, merlin reader, or package names.
- Reach for **Formal syntax** when you need to remember how JSX lowers or how children are passed.
- Reach for **Guides** when you already know your runtime and want the shortest working path.
- Reach for **Templates** and **Projects using mlx** when you want to start from code that already exists.
